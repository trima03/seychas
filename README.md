# Сейчас

Одна задача на экране, а новые мысли остаются в списке «На потом», чтобы вы могли вернуться к ним позже.

[Открыть приложение](https://trima03.github.io/seychas/) · [Релизы](https://github.com/trima03/seychas/releases)

Назовите конкретный результат и при желании запишите следующий шаг. Выберите удобную длительность, затем начните подход. Если отвлеклись, кнопка возвращения покажет вашу запись. Когда закончите задачу, нажмите «Готово», и она появится в истории.

Новая мысль сохраняется в боковом списке. Её можно взять в фокус, при этом прежняя задача вместе с записью следующего шага перейдёт в «На потом». Время отсчёта при переключении начинается заново. Удалённую мысль можно вернуть через уведомление в течение 12 секунд.

Таймер сверяется с моментом окончания, поэтому после перезагрузки или сна компьютера показывает оставшееся время. Во время явной паузы время не расходуется. При закрытом приложении или выключенном экране звукового сигнала нет, а завершение подхода будет показано при возвращении. Таймер сам не отмечает задачу выполненной.

## Данные и перенос записей

Записи хранятся в `localStorage` браузера на том адресе, где открыто приложение. Приложение не отправляет содержимое задач на сервер, не использует аналитику и не подключает сторонние шрифты. При открытии GitHub Pages сам хостинг получает обычный запрос страницы.

В окне «Мои данные» можно скачать Markdown с чекбоксами для Obsidian или резервную копию JSON. Импорт проверяет структуру файла и запрашивает подтверждение перед заменой текущих записей. Файл копии содержит ваши записи открытым текстом, поэтому храните его там, где им можно доверять.

Автоматической синхронизации между устройствами нет. Записи локального запуска и GitHub Pages находятся в отдельных хранилищах, поэтому для переноса используйте JSON. При очистке данных браузера локальные записи исчезнут.

В очереди помещается до 500 мыслей, в истории сохраняются последние 500 завершённых задач. В интерфейсе видны последние 50 записей истории, а экспорт включает всю сохранённую историю. Каждое текстовое поле допускает до 500 символов. Эти ограничения проверяются при импорте.

Если сохранённый файл повреждён, приложение блокирует редактирование и позволяет скачать исходную копию. Если хранилище недоступно или переполнено, на экране появляется предупреждение. При обнаружении изменений в другой вкладке приложение предлагает обновить страницу.

## Установка и офлайн

После первого успешного открытия приложение кеширует свои файлы. Для офлайн-режима нужен HTTPS или локальный сервер. На iPhone откройте приложение в Safari и выберите добавление на экран «Домой» в меню «Поделиться». На поддерживаемом компьютере браузер может предложить установку, а кнопка установки появится в «Мои данные».

Это обычный инструмент для организации работы. В нём нет медицинских оценок или обещаний результата.

## Локальный запуск

Достаточно Python 3, установка пакетов не требуется.

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

Откройте `http://127.0.0.1:4173`. На Mac можно запустить файл `Сейчас.command` двойным щелчком, тогда команда откроет браузер и оставит сервер в окне терминала. Для остановки нажмите Ctrl+C в этом окне. Через `file://` приложение запускать не следует, поскольку ES-модули и офлайн-режим требуют сервера.

## Проверка и публикация

Для тестов нужен Node.js 22 или новее, внешних зависимостей нет.

```sh
node --test
```

Тесты проверяют ход таймера после сна и перезагрузки, сохранность задачи при переключении, валидацию резервной копии и наличие файлов офлайн-кеша. Интерфейс написан на HTML, CSS и стандартном JavaScript.

В настройках репозитория GitHub Pages выберите источник GitHub Actions. Workflow проверяет код и публикует содержимое `dist`. В pull request выполняются только тесты. При изменении файлов приложения увеличивайте версию кеша в `dist/sw.js`, чтобы новая версия офлайн-файлов установилась после закрытия старых вкладок.

[Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) описывает workflow публикации, а [документация MDN](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers) объясняет работу офлайн-кеша и требование HTTPS.
